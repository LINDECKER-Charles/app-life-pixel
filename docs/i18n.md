# Internationalisation

## Rules

- **The repository is in English**: code, comments, documentation, commits, issues.
- **The interface is translated.** English and French at launch; adding a language requires no
  code change.
- **English is the source language and the fallback.**

## Catalogues are served, not bundled

Translations are loaded at runtime from an endpoint (D26 in [decisions.md](decisions.md)):

- the app downloads the **active language only**, and fetches another one when the user switches
  — the interface changes language without reloading;
- the **list of languages** comes from the same endpoint, so a language added on the server shows
  up in the settings without a new release of any app;
- no catalogue is ever compiled into the JavaScript bundle.

| Route | Content |
|---|---|
| `GET /i18n/languages.json` | available languages: code, name in that language |
| `GET /i18n/<language>.json` | the catalogue of one language |

`server` serves both with caching validators (`ETag`). The desktop app ships the same files and
serves them locally at the same paths, so it works offline. The Android app reads them from the
hosted server and carries English as its offline fallback.

The source files live in `i18n/` at the root of the repository — one JSON file per language plus
`languages.json`. The server serves them, the desktop app ships them, and emails are rendered from
them: every text has a single source.

On the client, Transloco is the library (D36): its HTTP loader fetches one catalogue at a time,
exactly as above, and it handles ICU plurals.

## Keys and messages

- **Keys** are lowercase, dot-separated, scoped by feature, and describe a meaning rather than a
  text: `editor.toolbar.pencil`, `export.dialog.title`, `errors.quota.storage_exceeded`.
- **Keys are append-only across releases.** A key never changes meaning and is not removed while
  a supported app still uses it: an outdated Android app keeps finding its keys.
- **Plurals and variants** use ICU MessageFormat:
  `{count, plural, one {# frame} other {# frames}}`.
- **Dates, numbers and file sizes** are formatted with `Intl` for the active language — never by
  concatenating strings, and not with Angular's locale-data pipes: every browser engine ships
  `Intl`, so a new language needs no locale data compiled into the app.
- **Choosing the language**: initialised from the browser or operating system, changed in the
  settings, remembered in the account (hosted) or locally (desktop).
- **Layouts leave room**: French runs noticeably longer than English. No fixed-width label.

## Back-end

- The API returns error codes and their parameters, never sentences. The interface translates
  `quota.storage_exceeded` through the key `errors.quota.storage_exceeded`.
- Emails are the only text the server renders, from the same catalogues (keys under `email.`),
  in the account's language, with English as fallback.
- MCP tool names, descriptions and schemas stay in English: they address the model. The error
  codes are the same as the API's.

## Adding a language

1. Copy `i18n/en.json` to `i18n/<language>.json` and translate every key, `email.` keys included.
2. Add the language to `i18n/languages.json`, with its name in that language.
3. Open the pull request only once the translation is complete: a missing key would show English
   in the middle of another language.

No code changes. Once the server is deployed, the language appears in every connected app
without an update; the desktop app gets it with its next release.

## Checks

CI verifies that every catalogue holds exactly the keys of `en.json`, that every ICU message
parses, and that `languages.json` lists every catalogue. Unused keys are reported, and removed
once no supported app uses them.
