# Desktop — T1 to T5, R1

The desktop app is `projects/app` packaged by Tauri 2, with `service` in-process on a local library
(D13): it works offline, without an account, and sends nothing (D24). It ships the `life-pixel`
CLI, so that a local agent reaches the same library over stdio.

## T1 — Desktop shell

`tauri/`, package `life-pixel-desktop` (`AGPL-3.0-only`), added to the workspace's members.

| Path | Content |
|---|---|
| `Cargo.toml`, `build.rs` | Tauri's library-and-binary layout; `build.rs` declares the app's commands in its manifest, so that each gets a permission |
| `tauri.conf.json` | below |
| `capabilities/default.json` | the main window: `core:default` and the app's commands, nothing else |
| `icons/` | generated by `cargo tauri icon` from a pixel-art source drawn in Life Pixel |
| `src/lib.rs`, `src/main.rs` | `run()`: plugins, state, commands |
| `src/state.rs` | `DesktopState`: `Library` over `LocalLibrary`, and the settings |
| `src/settings.rs` | `settings.json` in the app's configuration folder: `libraryPath`, `language`, `theme`, `motion` |
| `src/commands/` | `library.rs`, `export.rs`, `settings.rs`, `platform.rs` |
| `src/errors.rs` | `CommandError { code, params }`, serialized as the API's problems are |

`tauri.conf.json`, main settings:

```json
    "security": {
      "csp": "default-src 'self'; script-src 'self' 'wasm-unsafe-eval'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; connect-src 'self' ipc: http://ipc.localhost blob:; worker-src 'self'; object-src 'none'"
    }
  },
  "bundle": {
    "active": true,

    "license": "AGPL-3.0-only"

```

- The base configuration holds nothing that needs a file or a key the build may lack: T3's
  `tauri/bundle.conf.json` adds the sidecar (`bundle.externalBin`), T4's `tauri/release.conf.json`
  the updater artifacts, both passed with `--config` to `cargo tauri build`. So
  `cargo build --workspace` needs neither the sidecar nor a key, nor — in debug, where Tauri
  embeds no assets — the front-end build; if Tauri's context macro still requires `frontendDist`
  to exist, T1 makes that hold without building the app.
- The CSP allows no `'unsafe-eval'`, only `'wasm-unsafe-eval'` for the engine: nothing in the
  front end may evaluate code. ICU messages are therefore formatted by the shared i18n's
  `IcuTranspiler`, which walks `@messageformat/parser`'s syntax tree with `Intl`, not by
  `@messageformat/core`, whose compiled messages need `new Function`.
- From T1 on, CI's `rust` job installs Tauri's Linux system packages (WebKitGTK and its
  companions), since `cargo clippy --workspace` and `cargo test --workspace` now compile
  `tauri/`; on macOS and Windows, the system provides the webview.
- `cargo xtask build-desktop [--debug]` (T1) runs `cargo tauri build`, with `bundle.conf.json` once
  T3 has added it — never with `release.conf.json`, which only `release.yml` passes: a local or CI
  build needs no signing key.

### Commands

Arguments in camelCase; documents travel as base64 strings.

| Command | Arguments | Answer |
|---|---|---|
| `library_list_projects` | `cursor?`, `limit?` | Page of Project |
| `library_create_project`, `library_rename_project`, `library_duplicate_project`, `library_delete_project` | `name`; `id`, `name`; `id`, `name`; `id` | Project, or nothing |
| `library_list_animations` | `projectId?`, `query?`, `cursor?`, `limit?` | Page of Animation |
| `library_create_animation` | `projectId`, `document` | Animation |
| `library_open_document` | `id` | `{ summary, document }` |
| `library_save_document` | `id`, `version`, `document` | Animation |
| `library_rename_animation`, `library_move_animation`, `library_duplicate_animation`, `library_delete_animation` | as the HTTP API | Animation, or nothing |
| `library_usage` | — | `{ usedBytes, limitBytes: null }` |
| `export_save_files` | `files: [{ name, bytes }]` | the paths written, or `null` if the person cancels: one file opens the system's save dialog, several a folder picker |
| `settings_get`, `settings_set` | —; `settings` | Settings; changing `libraryPath` reopens the library |
| `settings_pick_library_folder` | — | the folder chosen in the system's dialog, or `null` |
| `platform_info` | — | `{ version, os, libraryPath, cliPath }` — `cliPath` from T3 |

- Project and Animation have the shapes of H6. The dialogs are opened from Rust
  (`tauri-plugin-dialog`), so the webview holds no file-system permission.
- The catalogues are part of `frontendDist` (F3's assets), served at `/i18n/` offline.
- `LIFE_PIXEL_LIBRARY`, when set, overrides the library folder, as it does for the CLI. Debug builds
  also honour `LP_EXPORT_DIR`, which saves exports there without a dialog: T5's tests use both.

**Tests**: every command on a temporary library, called directly with a test state; the settings
file written and read back; the library reopened after a path change; `cargo xtask build-desktop`
producing a Linux bundle in CI's `desktop` job.

**Tests** with `@tauri-apps/api/mocks` (`mockIPC`): each port's calls and errors; the providers

## T3 — Bundled CLI

- `cargo xtask build-sidecar [--target <triple>]` builds `life-pixel-cli` in release for the host's
  target triple, or the one given, and copies it to `tauri/binaries/life-pixel-<triple>` (`.exe`
  on Windows; the folder is ignored by Git). For `universal-apple-darwin`, it builds both macOS
  architectures and joins them with `lipo`. T3 makes `build-desktop` run it first, and adds
  `tauri/bundle.conf.json`, which lists it in `bundle.externalBin` as `binaries/life-pixel`.
- `platform_info.cliPath` is the sidecar beside the app's executable. Inside an AppImage, whose
  mount point changes at each launch, the app first copies the sidecar to
  `<data folder>/bin/life-pixel`, when missing or older, and gives that stable path.
- `settings/agents` (`frontend/projects/app/src/app/mcp/`) shows, with copy buttons, the command
  `claude mcp add life-pixel -- "<cliPath>" mcp --library "<libraryPath>"` and the equivalent
  `mcpServers` entry for an MCP client's JSON configuration, and explains what an agent can then
  do. **Keys**: `mcp.`.
- **Watcher**: `notify-debouncer-full` watches the library folder (300 ms) and emits
  `library-changed` with the project and animation ids concerned. Lists refresh. When the open
  animation changed on disk, the app reloads it if it holds no unsaved work, and otherwise asks:
  reload, keep mine — the next save meets H8's conflict dialog —, or save a copy.

**Tests**: the sidecar built and named for its triple; the watcher's event for a file written by
hand in a temporary library; the app's reaction, with and without unsaved work, on mocked events.

## T4 — Updater and release

- **Updater**: `tauri-plugin-updater` is registered only when the build received `LP_UPDATER_PUBKEY`
  and `LP_UPDATER_ENDPOINT` (read with `option_env!`): a local build has no updater.
  `tauri/release.conf.json` turns `bundle.createUpdaterArtifacts` on and carries the updater's
  public key for release builds only. It checks 10 seconds after start then every 6 hours, stays
  silent offline, and offers "Install and restart" — never restarting by itself.
- **`release.yml`**, on a `v*.*.*` tag, and by hand with a `dry_run` input that builds without
  publishing; every publishing job runs in the `release` environment, which requires the
  maintainer's approval (D32):

| Job | Does |
|---|---|
| `desktop` | a matrix on macOS (universal binary), Windows and Ubuntu 22.04: the Rust toolchain, wasm-bindgen-cli and `cargo xtask build-editor`, `npm ci --prefix frontend`, the Tauri CLI, `cargo xtask build-sidecar` for the matrix's target, then `tauri-apps/tauri-action` with `tauriScript: cargo tauri`, both overlays and the signing variables — Apple certificate and notarisation key, the Windows signing command of the service chosen at M5, `TAURI_SIGNING_PRIVATE_KEY` and its password, `LP_UPDATER_PUBKEY`, `LP_UPDATER_ENDPOINT` —, publishing a draft GitHub Release with the updater's `latest.json` |
| `npm` | checks that `player-js`'s committed build is current, then `npm publish --provenance --access public` through trusted publishing (`id-token: write`, no token) |
| `docker` | tags the images of the tagged commit `:vX.Y.Z` and `:latest` with `docker buildx imagetools create` |
| `attest` | `actions/attest-build-provenance` on the installers |
| `publish` | turns the draft release into a release once every job has passed |

- Android is left out until M6. devops.md's release section lists the secrets and the steps.

**Tests and checks**: actionlint; the dry run's structure reviewed; an unsigned local build, the
updater absent from it.

## T5 — Desktop end to end

- `tauri/tests/e2e/`: a small npm package (`selenium-webdriver`), with its Dependabot entry. It
  builds the debug app, starts `tauri-driver`, and drives the app with `LIFE_PIXEL_LIBRARY` and
  `LP_EXPORT_DIR` pointing at temporary folders.
- **Journey**: the app starts; a new animation is drawn with the keyboard and saved into a new
  project, then changed and saved again — a second save proves the local versions survive the trip
  through JavaScript —; the library lists it; a GIF export appears in the export folder;
  `life-pixel list --library <folder>`, run from the bundled sidecar, lists the same animation.
- CI's `desktop` job runs it on Linux under Xvfb, with WebKitGTK's WebDriver. `tauri-driver` cannot
  drive macOS: CONTRIBUTING.md gains a manual macOS checklist — install, draw, save, export, CLI,
  no updater.
- A passing T5 means M5 is done.
